REASONING + ACTING

程序执行，再把结果交回来。

ReAct 是一种组织模型与工具交互的方法。你写一个循环，让模型依据已有信息选择动作，执行工具，将真实结果放回对话，直到模型提交答案。

输入问题程序构造初始消息
→
模型生成Thought + Action
→
程序解析动作检查 JSON 与字段
→
执行工具得到 Observation

↳ 把动作与观察加入消息历史 → 再次调用模型

遇到 Finish 就取出答案并退出。解析失败会把错误交回模型。达到本实验的 6 步上限仍未提交，则记录 step_limit。

格式有没有标准？

原论文定义了交替推理与行动的流程，作者代码给出了文本格式。ReAct 本身没有要求所有实现共享一套 JSON 字段。本实验选择 JSON，便于 Python 校验与分发工具。

作者实现使用的文本约定

Thought 1: 需要先确定收购方。
Action 1: Search[Euromarché]
Observation 1: 收购方是 Carrefour。
Thought 2: 接下来查超市数量。
Action 2: Search[Carrefour]
Observation 2: 2016 年底有 1,462 家。
Action 3: Finish[1462]

上面用同一道题示意文本格式。作者 HotpotQA 代码生成 Thought 和 Action，由 Python 环境产生 Observation，再拼回提示。

本实验的动作协议

{
  "thought": "先确定收购方",
  "tool": "Search",
  "query": "Euromarché"
}

thought 是公开的简短行动理由，tool 指定工具，query 是参数。字段由实验程序定义。

把程序中的数据分清楚

一次循环可以跟踪四个变量。点开每种结构，查看它由谁产生、交给谁使用。

三个动作的完整字段

{"thought":"需要找实体","tool":"Search","query":"Carrefour"}
{"thought":"检查数量","tool":"Lookup","query":"2016","source":"E1"}
{"thought":"E1给出了数量","tool":"Finish","answer":"1462"}

这三行是独立的协议示例。Search 创建证据号；Lookup 查已经保存的证据；Finish 结束循环。source 必须引用已有证据才会命中。解析器要求所有字段为非空字符串，并检查字段集合。

Search 怎么工作？在该题候选资料中按「标题重合词数 × 3 + 正文重合词数」排序，返回第一条的前五句，最多 1,500 字符。Lookup 只能查询此前已经返回的片段。

代码就是这个循环

下面是便于阅读的流程骨架。client 负责 API，env 负责本地工具。原项目还记录轨迹、阶段和步数提醒。

def solve(question, titles, env, client, instruction):
    # 1. 构造模型可见的初始信息
    messages = [{"role": "user", "content":
                 instruction + question + str(titles)}]

    for step in range(6):
        # 2. 模型根据截至当前的消息生成一个动作
        raw = client.call(messages)
        messages.append({"role": "assistant", "content": raw})

        try:
            # 3. 解析并校验工具名、参数和字段类型
            action = parse_react_action(raw)
            if action["tool"] == "Finish":
                return action["answer"]

            # 4. Python 执行 Search 或 Lookup
            evidence_id, result = env.execute(action)
            observation = evidence_id + ": " + result
        except (ValueError, KeyError, TypeError) as error:
            observation = "Invalid action: " + str(error)

        # 5. 下次调用带上实际结果，让模型继续决定
        messages.append({"role": "user", "content": observation})

    return None  # 上限已到，仍无答案

为什么每次都传 messages？

本实验每次请求都显式携带历史。第一轮含问题和标题，第二轮再加入第一次动作与 E1，第三轮再加入第二次动作与 E2。模型因此可以根据新资料改变下一步。

谁负责停止？

模型可以选择 Finish，程序检查答案后返回。六步上限由 Python 强制执行。最后一步的提示只是提醒，模型仍可能继续选择 Search。
